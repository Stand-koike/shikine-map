# 総合運動公園イラストの位置合わせ

ブラウザは **WebP + 四隅の緯度経度（WGS84）** だけ読みます。GeoTIFF はそのままでは使いません。

---

## いま入れたもの（`geo_park.pgw`）

運営提供のワールドファイル: [geo_park.pgw](geo_park.pgw)（元ファイル名 `geo_park.pgw`）。  
画像: 1024×724 PNG（透明背景）→ `web/map.webp`。

ワールドファイル 6 行（ESRI、回転なし）:

| 行 | 値 | 意味 |
|----|-----|------|
| 1 | `0.160906757913` | ピクセル幅 X |
| 2 | `0` | 回転 |
| 3 | `0` | 回転 |
| 4 | `-0.160887096774` | ピクセル高さ Y（北が上なので負） |
| 5 | `39312.711632190942` | 左上ピクセル**中心**の X |
| 6 | `-145936.212328555208` | 左上ピクセル**中心**の Y |

**ワールドファイルには CRS がありません。**  
ピクセル幅 0.16・原点が数万単位なので **度ではなくメートル**です。下田・第 VIII 系の数値と合うため、変換は **EPSG:6676（JGD2011 / 平面直角座標系 第 VIII 系）→ EPSG:4326** と仮定しました。Tokyo Datum（EPSG:30168）だと数百メートルずれます。

回転項は 0 なので `MAP_IMAGE.bearing` は従来どおり **0**（pitch 45 もそのまま）。イラストの中身が斜めに描いてあるのは画像の絵であり、ジオリファレンスの回転ではありません。ピンは **実座標** で載るので、絵の建物とピンが数メートル〜数十メートルずれることがあります（絵のデフォルメ分）。現地合わせは lat/lng と `latOffset` / `lngOffset` で行います。

四隅はピクセル中心ではなく **ラスタ外縁**（GDAL の範囲）。Mapbox image source は NW → NE → SE → SW、`[lng, lat]`。

## これで足りるか

**地図画像を置くには足りる**（pgw + 同じサイズの PNG）。足りない／確認してほしいもの:

1. **CRS の確認** — 第 VIII 系（JGD2011）でジオリファレンスしたか。別ゾーンや Tokyo Datum なら四隅をやり直す。
2. **ピンの lat/lng** — 店舗マスタ・固定マスタの C/D 列（WGS84）。
3. **見た目の微調整** — 数メートルずれる場合は `config.local.js` の `latOffset` / `lngOffset`、または四隅の再指定。

---

## 別の TIF を出し直すとき（QGIS）

1. [QGIS](https://qgis.org/) で `.tif` を開く。
2. PNG/WebP を書き出し、`web/map.webp` に置く。
3. 範囲がメートルなら EPSG:4326 に再投影してから四隅を控える。
4. `MAP_IMAGE.coordinates` を NW / NE / SE / SW で更新し、`cacheVersion` を日付入りで変える。
